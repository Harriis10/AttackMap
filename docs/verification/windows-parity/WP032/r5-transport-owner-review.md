# R5 transport-owner review — bounded captured facts (design only)

No production edits or acceptance claim. CodeGraph verified `_finalize_fleet` calls `_effective_deployment_aliases` and `route_auth_signals` after child completion; the latter explicitly falls back to live PassSources without an index. Current deployment extractor reduces declarations across the ordered list of roots, including conflict/drop sets and precedence ranks.

Minimal cooperating API proposal:

- New internal `fleet_evidence_basis.py`: strict versioned `FleetEvidenceBasis` validator, capture builder and parent admission. Payload binds repo_id, normalized root, parent-issued child generation, ScanSnapshotIdentity snapshot_id/config_identity and protocol. Store parsed facts only, no raw bytes/index/source text/credentials. Source refs use exact snapshot path plus hash-kind and hash; raw and normalized-text hashes are different named domains. Resolve source refs only against the already reported captured identity, never by opening a path.
- Config extraction needs a narrow split: collect ordered `DeploymentDeclarationCandidate` (kind, key, value, rank, relative file, record ordinal, source ref), then reuse one shared reducer for existing single/full extraction and fleet replay. Transporting per-repo already-resolved aliases alone is unsafe: it loses rank/conflict tombstones and can revive a declaration dropped as ambiguous or change cross-root precedence. Parent replay order is requested repo order then captured file/record order, independent of completion order. Apply existing CLI override reducer last and remove discarded config origins.
- `route_auth_signals(..., *, index=...)` must require matching capture for the fleet builder. Build facts keyed by exact (file, method, case-sensitive path) plus captured line/handler discriminator where necessary, carrying present/absent/unknown and source ref. A missing/partial handler is unknown, never False. Existing downstream bool maps must receive only qualified complete facts, with explicit unavailable gating for trust-gap/anomaly conclusions that need unknown peers; default-get(False) cannot turn omission into a missing-control finding.
- Both `_run_single` interchange and `_run_fleet_serial` compute basis from `state.captured_index` explicitly before releasing state. Do not retain child indexes in parent. `FleetRepoResult` gets additive internal optional basis. `_load_repo_scan` retains public compatibility; a new internal loader can return basis alongside existing tuple without breaking fixture consumers. `_finalize_fleet` accepts admitted captured facts only. Legacy missing basis produces a typed unavailable note and no dependent live recomputation.

Admission/bounds: validate parent expected repo/generation before merging; match basis identity exactly to ScanResult.scan_snapshot; require every source hash reference to the corresponding raw_files or files identity entry in the declared hash domain. Count declarations, auth facts and source refs against exact capture/route counts plus declared finite protocol overhead; validate field lengths and serialized byte ceiling before parent model expansion. Extend existing result_bytes_limit rather than allocate an unreserved second buffer. If the bounded payload cannot carry all accepted facts, emit explicit partial/unavailable status; never silently select fewer sources or claim full coverage. Finite default internal interchange ceiling needs explicit reviewed policy because count-only fleet mode currently has no mandatory report-byte cap.

Focused acceptance: serial/parallel identical candidate replay; config change/delete/add and handler-auth edits after capture cannot affect finalization; cross-repo conflict/rank/order permutations; same-basename roots; unknown handler/partial capture cannot prove absence; malformed generation/root/snapshot/config/sourcehash/path/count/bytes reject only affected dependent facts; legacy basis missing; cancellation; exact CLI override origin; unchanged complete positive control. A fail-fast live-read counterexample is needed around finalization, not just snapshot transport unit tests. No filesystem/network sandbox or runtime authentication claim follows.

Likely lease: new module + scan_service.py/fleet.py, config_scanner narrow extraction/reducer split, anomalies.py explicit-index/tri-state helper. Contracts dependent unknown gating may need its own narrow lease after exact callers are reviewed. No pipeline changes required if returned PipelineState retains captured_index at current caller points; verify that lifetime before implementation.

## Exact cooperating API proposal (review before canonical lease)

1. config_scanner.py: add internal context-local declaration recorder (ContextVar defaultNone) observed at entry to `_declare_port/_declare_protocol/_declare_proxy`, before existing early-return/drop logic. Normal API/default reducer remains unchanged. `collect_deployment_candidates(root, *, index, budget)` asserts root/index identity and uses explicit pinned_index_scope only around existing extraction. Sink records ordered parsed candidate calls; reducer-produced notes are separated from parser notes so parent replay does not duplicate or lose ambiguity notes. `reduce_deployment_candidates(batches)` reuses the same three original reducers in requested repo/file/record order with recorder absent. No monkeypatching canonical module globals. Candidate kind/key/value/rank/kind_label/provenance is preserved; equal-rank disagreement permanently drops a key in the same shared reducer, including higher-rank later candidates exactly as today. Proxy last-equal-source behavior is retained.

2. anomalies.py: additive `route_auth_facts(scan, *, index)` returns route ordinal plus present/absent/unknown, source ref and reason. It must prove accepted captured text and valid handler span before absence can be asserted; missing line/text, partial capture or ambiguous binding is unknown. Existing route_auth_signals public/default behavior stays intact for compatibility. New captured helper never constructs a live PassSources fallback. Parent trusts absence only for qualified fact records; dependent trust-gap/anomaly logic must receive explicit availability, never coerce missing/unknown to False.

3. new fleet_evidence_basis.py: `build_basis(repo_id, generation_id, scan, index, budget)`, `admit_basis(payload, *, expected_repo_id, expected_root, expected_generation, scan, budget)`, strict schema/version and `CapturedSourceRef` table referenced by ordinal from candidates/auth facts. Validate references against ScanSnapshotIdentity raw_files or files using explicit hash domains. No raw source/text/index in payload. Identity agreement proves internal consistency with the owned core child report, not independent source authenticity. Parent-issued generation must exist for every child: reuse fleet_child_run_ids, mint missing internal run IDs before dispatch using existing --run-id forwarding, and verify published child generation identity. CLI/full wire schema is unchanged; only existing private interchange gains additive basis.

4. scan_service.py/fleet.py: build basis from returned state's explicit captured_index in both single-worker interchange and serial path; additive internal optional FleetRepoResult.evidence_basis; preserve existing `_load_repo_scan` tuple compatibility with an internal basis-aware loader. Validate before parent admission/retention and pass only captured admitted facts to finalization. Missing legacy basis yields unavailable limitations; never call live extraction as a fallback. C's small protocol-origin override lease must finish before this slice.

Bounds must be reviewed before implementation: source refs <= captured file count, auth facts <= scan route count, candidate ordinal/strings strict and all encoded facts charged to the existing worker result-byte allowance and retained-parent reservation. A count-only fleet currently has no mandatory result-byte ceiling: it cannot honestly claim bounded fact admission until an explicit finite internal FactBudget is selected. Candidate count cannot be capped merely by file count (one accepted config can contain many declarations). Prefer explicit fact payload budget + derived record ceiling/source-ref table, and mark dependent fleet reasoning partial/unavailable if the complete accepted fact set cannot fit; do not silently truncate records, reduce engine coverage or call this an optimization. Parser notes/unknown reasons also consume that budget. No numeric memory-safety claim follows from logical reservations.

Minimal review slices: (a) config recorder+shared replay and differential cross-root ambiguity/order fixtures; (b) bounded basis validation+generation/source refs; (c) captured auth tri-state+downstream unavailable gating; (d) serial/worker interchange/finalization with edit/delete/add/cancel fixtures. Expected scope several small modules/functions, not a pipeline rewrite. Exact source line counts should follow an owned prototype against the then-current R1/R2/R3/R4/R8 source, not this earlier sealed baseline.
