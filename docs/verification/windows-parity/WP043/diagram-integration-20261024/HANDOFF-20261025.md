## Concrete source findings

### 1. QA accepts black and glyphless output

`MainWindow.Capture.cs`, `CaptureLoaded`, approximately lines 174–227:

- Changes theme/size and selected destination.
- Waits one low-priority dispatcher turn, calls `UpdateLayout`, then captures.
- Calls `NativeCaptureProbe.Capture(...)` without `requireVisibleContent: true`.
- Writes a successful manifest even for black or glyphless PNGs.

`NativeCaptureProbe.cs`, approximately lines 19–98:

- `SettleRendering` waits only two `CompositionTarget.Rendering` frames.
- Optional `requireVisibleContent` checks only for any nonzero RGB pixel. It cannot
  detect missing text and would not reject the glyphless frames.
- Its own Scope correctly says these are not live-window/C24/C25 acceptance.

This is a confirmed verification-harness defect. It is not by itself proof of the
production glyph-loss root cause.

### 2. Hidden Diagrams can load and initialize as if visible

`MainWindow.xaml` keeps all destination panels in the visual tree and navigation only
changes panel `Visibility`.

`Diagram/DiagramWorkspaceView.cs`, approximately lines 61–68:

- `SetSelection` always awaits `legacy.SetSelection(value)`, including while hidden.
- Then `if (Visibility == Visibility.Visible) await ActivateInteractive();` checks
  only the workspace's own property, not collapsed ancestors. It can therefore start
  interactive loading even when the main Diagrams destination is hidden.

`Graphs/GraphWebView.cs`, approximately lines 110–145:

- `CanStart` likewise checks only its own `Visibility`, `IsLoaded` and current/old
  nonzero dimensions, not effective visibility through ancestors.
- A hidden graph can consequently initialize WebView2 after report binding or tab
  changes when its own properties and dimensions still satisfy the check.

This is a real lifecycle/unnecessary-work bug. It does not explain the zero-core
native-only user reproduction.

### 3. Completed-report binding performs excessive eager work

`MainWindow.xaml.cs`, approximately lines 412–456:

- `ReportAdapter.Load`, `ReportSectionAdapter.Load`, and
  `ParityOverviewAdapter.Load` each read and parse the same report, up to 64 MiB.
- After asynchronous reads, JSON parsing/projection continues on the UI thread.
- Manifest/report capture and hashing also add repeated work.

`MainWindow.Parity.cs`, approximately lines 125–134:

- `BindParityReport` populates Analyzer, Suppression, RiskPaths, EvidenceInventory,
  EvidenceOverview, Diagrams and AiArtifacts together, regardless of the visible tab.

`Overview/OverviewView.cs` rebuilds all its text/button elements while hidden.
`MarkdownView` similarly creates a full element tree when text is assigned.
`AI/AiArtifactProjection.cs`, approximately lines 121–149, loads every AI mode, not
just the selected one; artifact reads repeatedly revalidate selected identity.

These are credible UI-thread starvation, layout-pressure and delayed-settling risks.
They have **not** been proven to be the low-level mechanism that removes glyphs.

### 4. No demonstrated cross-thread XAML write

The reviewed watch and graph paths dispatch XAML work to the UI thread; graph/native
hosts also check `DispatcherQueue.HasThreadAccess`. Do not invent a cross-thread
binding explanation without new evidence.

## Recommended continuation order

1. **Separate harness proof from live-product proof.** Strengthen capture acceptance:
   reject black output, add a text/glyph-specific oracle rather than RGB-only checks,
   record failures, and wait for demonstrated theme/navigation/layout settling.
   `requireVisibleContent: true` alone is insufficient. Keep independent live-window
   visual review mandatory.
2. **Reproduce the actual user journey without using frame capture to drive it.**
   Load the same saved generation in native-only mode, use 1600x1000 dark, traverse
   all tabs repeatedly, and capture the real owned window independently. Record
   rendering diagnostics and verify every claimed keyboard action.
3. **Make a minimal lazy/effective-visibility patch.** Prevent hidden Diagrams,
   legacy diagrams and GraphWebView from loading/initializing until effectively
   visible through ancestors. Add focused tests for collapsed ancestors and tab
   switching. Do not claim this fixes global glyph loss without A/B live evidence.
4. **Reduce completed-report UI-thread work separately.** Prefer one bounded report
   read/parse and background projection; bind heavy hidden views lazily. Preserve
   report identity/integrity checks and current CLI behavior. Keep this as a focused
   performance/lifecycle change, not an assumed glyph repair.
5. Only after a candidate is qualified by repeated independent live A/B runs should
   source promotion, rebuild and portable acceptance resume. Do not use a single
   positive observation or a successful capture manifest as acceptance.
