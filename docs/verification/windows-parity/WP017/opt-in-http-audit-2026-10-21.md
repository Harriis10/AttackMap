# Opt-in local HTTP audit (WP017 preparation)

This observer records AttackMap's own nonstreaming OpenAI Responses exchanges.
It is disabled by default and is not a provider attestation. Bind its source
hashes, or the frozen executable containing it, to the run being verified.
No live provider request has been performed for this implementation evidence.

Set these variables only on the caller-owned QA native process:

```text
ATTACKMAP_QA_HTTP_AUDIT_DIR=<absolute existing local caller-owned QA directory>
ATTACKMAP_QA_HTTP_AUDIT_NONCE=<unique 1..64 character ASCII letters/digits/_/->
```

The only supported origin/base is `http://127.0.0.1:1234/v1`; method/path is
`POST /v1/responses`, model `cyberstag-security-26b-a4b-v1`, streaming disabled.
Invalid audit configuration fails before provider dispatch. The normal SDK
DefaultHttpxClient factory, trust_env=False, follow_redirects=False, pooling,
timeouts and retry settings are preserved. No endpoint/model/request mutation,
new network request, global logging or LM Studio setting change is introduced.

Each client exclusively creates a fresh
`wp017-<nonce>-<pid>-<uuid>/http-audit.jsonl` beneath the supplied directory.
Existing files are never overwritten. The JSONL records audit_started,
attempted_dispatch, http_response_received and observation_complete separately.
Attempts lacking a returned HTTP response are not confirmed server receipts.
Observation completion is not necessarily model completion: only a 2xx response
with JSON status completed, the exact model and nonempty extracted output is
marked completed. Missing provider IDs remain null; attempt UUIDs are local.

The observer reads the nonstreaming response bytes the SDK subsequently receives
from its cache. It stores full body SHA256/length, never the full body. Only the
actual generated output text is saved as an exclusive `output-<attempt>.utf8`
file, with its SHA256 and UTF-8 byte length in JSONL. Request headers, input,
prompts, arbitrary response headers and error messages are not persisted. A
provider can echo input in generated output, so these output files belong in
private QA evidence and are not automatically public release artifacts.

JSON inspection is bounded at 2 MiB; larger or malformed bodies remain unknown.
The original response is neither truncated nor replaced. The log is bounded to
512 events / 1 MiB. A failed/missing observation, overflow or altered output is
not acceptable proof; response-side audit write failure does not replace a real
provider reply. Original network errors propagate and no retry is added.

`tools/verify_wp017_live.py` accepts:

```json
{
  "provider_event_source": "attackmap-httpx-audit",
  "audit_nonce": "unique-run-nonce",
  "provider_audits": [{"path": "relative-or-absolute/http-audit.jsonl", "sha256": "..."}],
  "actual_http_requests": 1,
  "completed_responses": 1
}
```

These fields supplement its existing native request, selected manifest/artifact,
display/capture/export and engine identity fields. Include all audit logs from
the owned run interval. The helper checks sequences/nonces, request/response
pairing, hash-bound generated bytes, and exact model/origin. It requires no raw
headers/prompts/full response body or external cryptographic attestation.
`actual_http_requests` counts returned HTTP exchanges; attempted dispatches are
separate. A missing response leaves the audit incomplete. Source-native evidence
remains interim; package provenance and actual visual/manual decisions remain
separate. The helper's `passed` means evidence consistency, not roadmap closure.
