The recent-repository codec is pure JSON decode/encode, not a file store. It preserves original corrupt/unknown-version input without implicitly replacing it, rejects duplicate keys/invalid identities and bounds input to 64 KiB/50 entries/depth 16. Supported additive metadata remains represented with JsonExtensionData. Its private SchemaVersion=1 describes this preparation payload only; it is not an engine schema or a committed LocalSettings migration. Repository identity is an explicit stable ID/full path, independent of display basename. Decoding does not probe paths, launch watchers, load reports or start scans.

Generation artifacts bind exact repository ID, generation ID, report path and SHA-256. Core supplied generation order and pinned/current flags are preserved. Missing repositories are recoverable; historical report artifacts remain separately selectable. Completed analysis with failed policy stays completed and openable. Unknown/noncompleted states never become completed based on policy text.

Previous/custom/none and fail-on-new-high are callback-only **next-run options intents**. Previous snapshots the supplied current completed generation when chosen; a later current pointer does not advance the captured baseline. Custom requires an explicit same-repository artifact identity. No baseline fallback is selected if identity is unavailable. Proposal-only retention candidates exclude pinned/current/selected/captured-baseline generations; there is no deletion method or filesystem mutation. Host/core must independently protect the captured baseline and revalidate retention immediately before any real change.

Historical loads and compare/pin/custom-picker callbacks carry selection epoch and exact artifact hashes. Repository/generation changes invalidate older replies. Comparison requests issue a new epoch and clear older displayed comparison; accepted results retain exact supplied core category names/counts/IDs/order. No diff inference from title/line drift or UI rescoring occurs. Pin is intent-only and does not update flags locally; the host must obtain a refreshed core snapshot after completion.
