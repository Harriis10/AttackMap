# Existing-target fallback / new-target-only stage design

Design only, pending root review. All three completed candidate copies/evidence remain immutable; canonical source/tests remain held.

Third prototype passed byte/failure/identity checks. Its ABBA medians were baseline CPU 2.0703125s, wall 2.8400152s, lifetime job peak 161,546,240 bytes; stage-copy CPU 2.359375s, wall 3.8246858s, peak 126,330,880 bytes. The same actual 36,895,649-byte report was used. Logical extra stage write+read totals 73,791,298 bytes, not measured physical disk traffic. Target file identity stayed unchanged. However, a temporary file inherited parent permissions rather than a specially restricted existing target ACL; this remains a valid blocker for that existing-target branch.

Smallest proposed variant:

1. If the destination already exists **or is a symlink**, execute the original expression and writer directly: `safe_write_text(out, target, json.dumps(value, indent=2) + "\n")`. Do not allocate a stage, generate its name, create directories, or emit any report content elsewhere. Keeping serialization before ordinary writer checks also preserves legacy exception ordering in this branch. Existing file identity/ACL/hardlink behavior and peak-memory cost remain legacy. A target that disappears while that ordinary path runs follows the original behavior.
2. Only an initially absent non-symlink destination uses section-C encode into an exclusive owned stage with the existing shared path/open checks. Document that the temporary inherits the output parent's permissions; no equality to a concurrent/new destination ACL is claimed. This is appropriate only where that parent is already an authorized report-output location. No general ACL abstraction or permission copying.
3. After successful stage encode/close, recheck the target and path. If any entry appeared, fail closed and remove only the owned stage. **An exists recheck alone is insufficient.** The final target open must use `O_WRONLY | O_CREAT | O_EXCL | O_NOFOLLOW` through the shared path/open checks. O_EXCL closes the race between recheck and open; a concurrently created ordinary file, hardlink or symlink is never truncated. No fallback after staging: refuse rather than silently treating a concurrent restricted target as a legacy-existing overwrite.
4. After acquiring the new target descriptor exclusively, copy the stage in bounded 64 KiB chunks, close, and unlink only the owned stage. Final-copy I/O failure may leave a new partial target, as the original new-file writer can. No stronger per-file atomic/durability or cleanup promise. Generation validation/pointer commit remains unchanged and must keep prior current generation valid.

The deliberate race behavior is stronger than legacy: a target created during encoding causes FileExistsError/UnsafePathError instead of being overwritten. Initial classification cannot lock parent permissions or prevent another actor from changing ACLs after either file creation; no temporary confidentiality equivalence under concurrent permission mutation is claimed. Do not automatically retry/fallback or remove that actor's file. Existing-parent and symlink protections stay exactly at the shared policy boundary; this design does not fix unrelated pre-existing ancestor races.

Focused tests before promotion:

- Existing normal/restricted-target branch: patch stage creation/UUID factory to fail if called; byte-for-byte original output, same file ID, unchanged target security descriptor where available, ordinary encoder/write failures and exception ordering. Existing-target path must produce no stage content. Existing-target byte/memory behavior explicitly excluded from optimization claims.
- Absent-target branch: same eight JSON goldens, complete actual report bytes/return/order, failure phase distinctions and foreign-stage collision preservation. Reuse prior owned-process ABBA only after the final variant exists; no full pipeline.
- Deterministically create an ordinary destination, symlink and hardlink immediately before commit; ensure recheck refuses without modification. Separately create one after recheck but before `_open_output_fd`; O_EXCL must refuse. Preserve actor-owned bytes/ID/ACL and remove only owned stage. No automatic overwrite retry.
- Actual Windows path/symlink tests and successful new-target checksum/generation validation. Inject pre-target and final-copy failures; previous current pointer/generation stays valid. Do not claim a partially written new target rolled back.
- Report generation uses a fresh unique destination in the normal atomic generation workflow; persistent output-format/publication tests must verify that path without a full repository scan. Legacy overwrite paths retain original behavior.

Largest section/scalar remains unbounded, dictionary construction/return remains live, and scan-stage memory remains separate. No 50k/100k, default, coverage, analyzer, or budget change follows from this design.
