# Publication memory slice — design only

No canonical source changes, prototype, new scan, or larger campaign is authorized by this note.

The retained 10k samples peak at 1,721,303,040 private bytes, elapsed 2305.215s, during the `publish` label. Scan/merge separately peaks at 857,772,032 bytes. First observed publish entry is 2107.420s; its recorded timed duration is 208.461s. The peak therefore precedes inferred timed publication completion by about 10.666s. Entry-only labels persist through later manifest work, but this particular peak is earlier. See `10k-stage-memory-offline-2026-10-21.json` for exact samples, source hashes/timestamps, artifact times and alignment qualifications.

Faulthandler dump 38 (nominal 2280s after setup, not an exact simultaneous sample) shows `json.encoder.iterencode` through `report.py:123`, serializing the monolithic report. The report's final filesystem write is 2310.61s after runtime creation and its size is 367,647,004 bytes. Dump 39 shows later artifact-manifest file hashing. These observations prioritize serialization investigation; they do not attribute all peak bytes to one allocation.

Current implementation retains the live scan and surfaces, then builds `defensive_review_json` and `review_context_pack`. `json_report` additionally retains `scan.model_dump()`, surface/finding/path dumps, and references to the review/context dictionaries. `json.dumps(json_report, indent=2) + "\n"` produces the entire report text before `safe_write_text` performs text encoding/write. The review and context standalone writes use the same complete-string pattern. `write_reports` returns the report dictionary for later section publication, so dropping it or replacing its shape would be a separate contract change.

The smallest candidate is a narrowly scoped chunked JSON writer used initially for only `attackmap-report.json`. Keep the exact same `json_report` construction/return value, dictionary order and fields. Iterate `json.JSONEncoder(indent=2)` output with all current defaults, append exactly one newline, and pass chunks through a shared output-path/open policy equivalent to `safe_write_text` (same UTF-8, newline="", checks, flags, close-on-error). Coalesce small chunks to a finite target, e.g. 64 KiB, without collecting the full iterator. A single JSON scalar may exceed that target: do not claim a universal 64 KiB allocation ceiling. Do not invoke validators, rescore, trim evidence, change output format, or omit repeated fields.

This first slice deliberately retains the returned dictionary and existing review/context objects. It targets whole serialized strings/concatenation/encode copies only; it cannot claim to solve scan-stage memory or establish a safe 100k bound. Chunked checksums for existing files and standalone review/context writes are later independently reviewed slices, not part of this first candidate. Current artifact-manifest hashing calls `read_bytes()` for the 367 MB report and other outputs, but retained samples do not make that the global peak.

Atomicity is generation-level: `_run_scan_published` writes the staged generation, validates/publishes it, then exports compatibility files. Keep that flow and manifest-last pointer commit unchanged. Existing `safe_write_text` directly truncates/writes individual files; it is not a per-file atomic replace. The measurement itself used `atomic_output=False`, so its samples do not qualify generation commit/validation or compatibility-copy peak. A failed chunked write must propagate before publication; the previous current-generation pointer remains intact. Do not broaden failure cleanup to unrelated files. No new per-file atomic semantics are implied.

Before any owned prototype, root should review the shared-writer policy boundary. Proposed validation in a fresh owned copy:

- Exact byte comparison against `json.dumps(value, indent=2) + "\n"`: insertion order, nested arrays/maps, Unicode/astral/escapes, empty values, booleans/null, floats including negative zero and existing NaN/Infinity behavior, integer keys, long scalar values. Preserve existing serialization errors and no caller mutation.
- Actual retained 1000-report decoded dictionary, baseline/candidate byte SHA equality, uninstrumented interleaved owned-process peak/current memory. Separate serialization-only measurements from model-construction and publication overhead.
- Inject encoder/write failure: no published pointer change, previous generation still validates, failed staged generation is unavailable as current, diagnostic retained; no unrelated cleanup.
- Existing output-format, symlink/output-path, artifact-manifest checksum and publication rollback tests. Include real Windows newline/UTF-8 byte checks; generation-level manifest/reference integrity must remain exact.

Add worker event markers in a new owned measurement adapter for before/after report dictionary construction, encoder start/end, file write, manifest section serialization and file hashing. Record paired wall/monotonic clocks and observer read start/end, scalar sizes/counts, no extra model copies. This is a measurement design only; no full pipeline or 50k/100k launch follows from it.
