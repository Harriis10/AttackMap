# C23 report, source and selected-export composition

This pure .NET console project links the production adapters and source/export helpers read-only. Its synthetic golden report combines conflicting candidate observations, unknown association/control/trust status, explicitly truncated coverage, an unsupported-language limitation, duplicate accepted source paths and a finding without any location.

```powershell
dotnet build desktop/windows/C23ReportComposition.Tests -c Release
dotnet desktop/windows/C23ReportComposition.Tests/bin/Release/net8.0/C23ReportComposition.Tests.dll ABSOLUTE_FRESH_PROOF_JSON
```

All live source and export fixtures use a fresh system temporary directory. No real analyzer or network runs. Seventeen checks establish preservation of supplied conflicts/provenance/uncertainty; separate distinct/aggregate coverage counts; no invented source target for missing locations; live Unicode unsupported-extension inspection with unknown scan-time integrity; and exact run-A export after a separate current pointer changes to run-B.

Audit of existing independent tests found prior coverage for long/non-ASCII live paths, whole-file hash unchanged/changed, excerpt hashes never promoted, invalid/missing/reparse paths, source size and location truncation, long export destinations, source collisions, changed source/manifest/review preservation, and unverified legacy Markdown refusal. Those scenarios were not duplicated here.

Still unproven: actual unsupported-language analyzer behavior, manual finding selection/source picker/reveal/copy, conflict presentation task comprehension, keyboard/Narrator task completion, and visual layout/contrast/text scaling. Supplied coverage truncation is preserved; this fixture does not establish real analyzer truncation behavior or complete C23 acceptance.
